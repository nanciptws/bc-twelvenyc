03. Account Configurator & Permission Architecture

One company policy, enforced everywhere

ADMIN

Twelve Inc. Admin

Authenticate → search/select existing company → load policy → select brands/products → save.

EXACT

BigCommerce B2B Company

Company Domain supports registration. Account Configurator stores permission JSON.

BACKEND

Company Access Validation

Confirm the company, validate its saved permissions, block unauthorized access and recheck when needed.

Mandatory enforcement surfaces

Homepage & Navigation

Only approved merchandising and destination links.

Brand, Category & PLP

Filter listings without exposing restricted metadata.

Search Results

Authorize server results, counts, suggestions and facets.

PDP & Direct URLs

Deny restricted products even when URL is known.

Cart

Revalidate every mutation and all current line items.

Order Request

Final server-side permission check before order creation.

Saving Company Configuration

Validate company and catalog IDs → apply versioned JSON schema → detect conflicts → optimistic concurrency → update exact Account Configurator field → record actor, time and before/after hash → invalidate cached policy. Customers have no permission-write path.

04. Order Request, Status, Reference & Notifications

One order, one stable reference, two independently retryable emails

Custom Form

Cart, brand, regions, date, address, freight, allocations, notes and attachments.

Server Validation

Trusted identity, company, cart, catalog, permissions, inputs and files.

Duplicate Prevention

Use a unique submission key and stable reference such as TWV-140 to prevent duplicate orders.

Freight Decision

Choose the configured BigCommerce order status from the freight checkbox.

Required status logic

Freight checkboxBigCommerce order statusProcessing rule
CheckedFreight RequestCreate one order using the tenant-configured status ID.
UncheckedOrder RequestCreate one order using the tenant-configured status ID.

Order and notification plane

BigCommerce Order

Validated products/quantities, customer-company association, correct status and returned order ID.

Request Ledger

Idempotency key, reference, order ID, state, attempts, errors and transaction/outbox boundary.

Email Outbox

Customer confirmation plus internal email to ELC_NACR_GLOBAL@twelvenyc.com, both using the same reference.

CRITICAL

Failure-safe State Flow

RECEIVED → VALIDATED → REFERENCE_RESERVED → ORDER_CREATING → ORDER_CREATED → EMAIL_QUEUED → COMPLETE

On timeout: reconcile before safe retry. On email failure: retry the email record only and never recreate the order.

Order ID, customer/company, line items, quantities, configured status ID/name and reference linkage.

OUTBOX

Notifications

Reference, recipient, template version, provider ID, attempts and queued/sent/failed timestamps.
